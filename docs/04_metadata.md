## Half-Hourly Smart Meter Data

**File pattern:** `serl_smart_meter_hh_edition08/serl_half_hourly_<year>_<MM>_edition08.csv`  
**Grain:** one row per household per 30-minute UTC period  
**Coverage:** UTC calendar month (00:00:00Z on the 1st to 23:30:00Z on the last day)

| Column | Type | Description |
|---|---|---|
| PUPRN | text | Pseudonymised household identifier (8-character alphanumeric) |
| Read_date_time_UTC | text | Timestamp of the reading in UTC — format `YYYY-MM-DDTHH:MM:SSZ` |
| Read_date_time_local | text | Timestamp in Europe/London local time with timezone label (GMT or BST) |
| Read_date_effective_local | text | Local calendar date the reading belongs to (format `DD/MM/YYYY`); midnight UTC reads roll to the previous local date |
| HH | int (nullable) | Half-hour interval index within the local day (1 = 00:00–00:30, 48 = 23:30–00:00); `NA` if the timestamp is not on a 30-minute boundary |
| Valid_read_time | boolean | `True` if HH is not NA (timestamp is aligned to a 30-minute boundary) |
| Elec_act_imp_hh_Wh | int | Electricity active import for the half-hour period (Wh) |
| Elec_react_imp_hh_varh | int | Electricity reactive import for the half-hour period (varh) |
| Elec_act_exp_hh_Wh | int | Electricity active export for the half-hour period (Wh); non-zero only for households with solar/battery export |
| Elec_react_exp_hh_varh | int | Electricity reactive export for the half-hour period (varh) |
| Gas_hh_m3 | float | Gas consumption for the half-hour period (m³); `0` or small value for households without gas |
| Gas_hh_Wh | int | Gas consumption converted to energy (Wh) using CV = 39.5 MJ/m³ (~10 972 Wh/m³) |
| Elec_act_imp_flag | int | Data quality flag for `Elec_act_imp_hh_Wh` — see [Flag codes](#flag-codes) |
| Elec_act_exp_flag | int | Data quality flag for `Elec_act_exp_hh_Wh` — see [Flag codes](#flag-codes) |
| Elect_react_imp_flag | int | Data quality flag for `Elec_react_imp_hh_varh` — see [Flag codes](#flag-codes) |
| Elect_react_exp_flag | int | Data quality flag for `Elec_react_exp_hh_varh` — see [Flag codes](#flag-codes) |
| Gas_flag | int | Data quality flag for `Gas_hh_m3` — see [Flag codes](#flag-codes) |

## Daily Smart Meter Data

**File pattern:** `serl_smart_meter_daily_edition08/serl_smart_meter_daily_<year>_edition08.csv`  
**Grain:** one row per household per calendar day  
**Note:** generated by this project

| Column | Type | Description |
|---|---|---|
| PUPRN | text | Pseudonymised household identifier |
| Read_date_effective_local | text | Local calendar date (format `DD/MM/YYYY`) |
| Read_date_time_UTC | text | UTC midnight timestamp corresponding to the effective date |
| Valid_read_time | boolean | `True` if the daily timestamp is valid |
| Elec_act_imp_flag | int | Data quality flag for daily electricity active import — see [Flag codes](#flag-codes) |
| Valid_hh_sum_or_daily_elec | boolean | `True` if either the daily electricity reading or the sum of half-hourly readings is valid and usable |
| Elec_sum_match | int | `1` if the daily electricity meter read matches the sum of valid HH readings; `0` if there is a discrepancy |
| Gas_flag | int | Data quality flag for daily gas — see [Flag codes](#flag-codes) |
| Valid_hh_sum_or_daily_gas | boolean | `True` if either the daily gas reading or the sum of half-hourly gas readings is valid and usable |
| Gas_sum_match | int | `1` if the daily gas meter read matches the sum of valid HH readings; `0` if there is a discrepancy |
| Elec_act_imp_d_Wh | int | Electricity active import as reported by the daily meter read (Wh) |
| Unit_correct_elec_act_imp_d_Wh | int | Unit-corrected electricity active import daily read (Wh); corrects for known unit-reporting errors in some meter types |
| Elec_act_imp_hh_sum_Wh | float | Sum of valid half-hourly electricity active import readings for the day (Wh) |
| Gas_d_m3 | float | Gas consumption as reported by the daily meter read (m³) |
| Gas_hh_sum_m3 | float | Sum of valid half-hourly gas readings for the day (m³) |

## SERL Survey Data

**File:** `serl_survey_data_edition08.csv`  
**Grain:** one row per household  
**Source:** Household survey conducted at recruitment; the field list and value codes are read directly from `data/reference/serl_survey_data_dictionary_edition07.csv` (also copied into `data/mock/serl_survey_data_dictionary_edition08.csv` at generation time). The table below is a representative subset — the dictionary CSV is the authoritative full column list.

| Column | Type | Description |
|---|---|---|
| PUPRN | text | Pseudonymised household identifier |
| Survey_version | text | Survey wave the household completed (Wave1, Wave2, Wave3) |
| Recorded_date | text | Date the survey was recorded (YYYY-MM-DD) |
| Collection_method | text | How the survey was completed (Online, Postal) |
| Language | text | Language in which the survey was completed (English, Welsh, Unknown) |
| A1 | int | Whether the household knew they had a smart meter before being contacted about the study (1=Yes, 2=No) |
| A3xx | int | Type of central heating, one binary column per fuel/system (A301–A310; 0/1) |
| A4xx | int | Central heating controls present, one binary column per control type (A401–A406; 0/1, -9 = not applicable) |
| A9xx | int | Circumstances in which heating is adjusted, one binary column per scenario (A901–A907; 0/1) |
| A10 | int | How heating controls are adjusted when the house is unoccupied (1=Always … 6=Not applicable) |
| A11 | int | Whether there are living spaces not normally heated in winter (1=Yes, 2=No, -2 = no answer) |
| A12_Taps_* / A12_Shower_* | int | Hot-water technology present for taps/showers, one binary column per technology; `A12_Taps_SWH` / `A12_Shower_SWH` (solar water heating) are aligned with `has_solar_thermal` in `household_traits.csv` |
| A14 | int | Effort made to limit household energy usage (1=A great deal of effort … 4=No effort at all) |
| A1501 / A1502 | int | Window-opening frequency on a typical cold / warm day (1=Always … 5=Never) |
| A16xx | int | Additional heating/insulation checklist items, one binary column per item (A1601–A1610; 0/1) |
| B1 | int | Type of accommodation (coded; -2 = no answer) |
| B2 | int | Whether the accommodation is self-contained (1=Yes, 2=No, -2 = no answer); ~3% of mock households are marked not self-contained |
| B4 | int | Whether the accommodation is owned or rented (coded; -2 = no answer) |
| B5 / B5_err | int / boolean | Number of rooms available for use by the household, and whether it was corrected |
| B6 | int | Number of those rooms that count as bedrooms (-2 = no answer, -4 = unusable response) |
| B7 | int | Whether the household can keep comfortably warm in cold winter weather (1=Yes, 2=No) |
| B8 | int | Whether the household has problems with condensation, damp or mould (1=Yes, 2=No) |
| B9 | int | When the accommodation was built (coded decade band) |
| B10xx | int | Appliances present in the accommodation, one binary column per appliance (B1001–B1014; 0/1) |
| C1 / C1_new | int | Number of people in the household, and the corrected/recoded value |
| C2_Male_* / C2_Female_* | int | Household occupant counts by gender and age band (0-15, 16-24, 25-44, 45-64, 65-74, 75-84, 85+); generated together so they sum to `C1_new` in the large majority of rows |
| C2_sum / C2_sum_diff / C2_error | int / int / boolean | Sum of the C2 age-band columns, its difference from `C1_new`, and whether they disagree |
| C2_tot_child / C2_tot_adult / C2_tot_65_plus / C2_all_65_plus | int / int / int / boolean | Derived household-composition totals from the C2 columns |
| C301–C307 / C3_sum | int | Working status per adult category (30+ hrs, <30 hrs, long-term sickness, unemployed, student, retired, other), and their sum — consistent with `C2_tot_adult` in most rows |
| C4 | int | Number of people in the household with a degree or higher qualification (-2 = no answer, -1 = don't know / prefer not to say) |
| C5 | int | Whether the household has a plug-in electric vehicle (-2 to 2); aligned with `has_ev` in `household_traits.csv` |
| C6 | int | When the household charges an electric vehicle at home; `-9` (not applicable) unless `has_ev` |
| D1 | int | Age group of the main respondent (coded band) |
| D2 | int | Gender of the main respondent (coded) |
| D3 | int | Current employment status of the main respondent (coded) |
| D4 | int | How well the household manages financially (coded; -3 to 5) |
| *_err | boolean | Error/edit flag for the corresponding variable (True if a correction was applied) |
| *_sum / *_diff | int | Derived sum or difference variable (used for multi-part questions) |
| *_text / *_Other | text | Free-text response for open-ended or "other" options |

> Missing value codes: `-1` = don't know, `-2` = no answer / refused, `-9` = not applicable.

## COVID-19 Survey Data

**File:** `serl_covid19_survey_data_edition08.csv`  
**Grain:** one row per household  
**Source:** COVID-19 lockdown follow-up survey; field list and value codes read from `data/reference/serl_covid19_survey_data_dictionary_edition07.csv` (also copied into `data/mock/serl_covid19_survey_data_dictionary_edition08.csv`).

| Column | Type | Description |
|---|---|---|
| PUPRN | text | Pseudonymised household identifier |
| Q1 / Q2 | int | Current lockdown/working situation (Q1), and a routed follow-up (Q2); `Q2` is fixed to `4` when `Q1 = 6` ("I don't have this") |
| Q3 / Q3a_* | int | Whether a specific circumstance applies (Q3), with checklist follow-up columns answered only when `Q3 = 1` (`NaN` otherwise) |
| Q4_* | int | Outdoor-access checklist columns (always answered; 0/1) |
| Q5–Q10 | int | Direct option-set questions about lockdown behaviour and circumstances |
| Q6_* | int | Window-opening frequency checklist (non-sequential codes 7, 14–18) |
| Q11a_* / Q11b_* | int | Appliance ownership flags (Q11a) and appliance use vs pre-lockdown (Q11b); a `Q11b_*` column is `NaN` when the corresponding `Q11a_2_<n>_1` flag indicates the household doesn't have that appliance |
| Q12a_* / Q12b_* | int | Same pattern as Q11a/Q11b for a separate device checklist |
| Q17–Q21 | int | Further direct option-set questions |
| Q22a_* / Q22b_* | int | Time-of-day checklist columns (0/1) |
| Q24 / Q25 | int | Month-coded questions (1–12) |
| RC1 / RC2 | int | Research consent flags |
| Finished | int | Whether the respondent completed the survey (0/1) |

> Missing value codes: `-1` = don't know, `-2` = no answer / refused, `-9` = not applicable. Columns not covered by an explicit rule above are populated from the dictionary's direct option list where one exists, or left blank (`NaN`) otherwise.

| E2 / E3 | text | Numeric satisfaction scales (E2: 0–10, E3: 0–11); `NaN` if not answered |

**File pattern:** `serl_climate_data_edition08/serl_climate_data_<year>_<MM>_edition08.csv`  
**Grain:** one row per ERA5 grid cell per UTC hour  
**Note:** generated when weather download is enabled and CDS credentials are configured; produced by `WeatherDownloader._nc_to_csv` in `weather_downloader.py`

| Column | Type | Description |
|---|---|---|
| grid_cell | text | ERA5 spatial grid cell identifier (format `<col>_<row>`, zero-padded to 2 digits, e.g. `03_28`) |
| analysis_date | text | Local calendar date (DD/MM/YYYY, e.g. `01/08/2019`) |
| date_time_utc | text | UTC timestamp of the observation (YYYY-MM-DDTHH:MM:SSZ, e.g. `2019-08-01T03:00:00Z`) |
| 2m_temperature_K | float | Air temperature at 2 m above ground (Kelvin; subtract 273.15 for °C) |
| surface_solar_radiation_downwards | float | Accumulated downward solar radiation at the surface (J/m²); divide by 1 800 for average W/m² per half-hour |
| total_precipitation | float | Accumulated total precipitation (metres of water equivalent) |
| 10m_u_component_of_wind | float | Eastward wind component at 10 m (m/s) |
| 10m_v_component_of_wind | float | Northward wind component at 10 m (m/s) |

> There is **no `PUPRN` column** in this file — climate data is generated per grid cell, not per household. The link to households lives in `serl_participant_summary_edition08.csv`'s `grid_cell` column; join on `grid_cell` (and, for hourly-to-half-hourly alignment, on date/time) to attach weather to a PUPRN.

## Flag codes

All flag columns use the same integer coding:

| Code | Meaning |
|---|---|
| `1` | Valid reading |
| `0` | Missing or null reading |
| `-1` | Meter rollover — value at or above physical meter maximum (16 777 215 Wh for electricity; 16 777.215 m³ for gas) |
| `-2` | Implausibly high value — above the "very high" threshold (24 000 Wh for electricity import; 5 000 Wh for electricity export; 8.0 m³ for gas) |
| `-5` | Invalid read time — timestamp is not aligned to a 30-minute boundary (`Valid_read_time = False`) |

> `-3` (negative reading) and `-4` (unit error) are recognised by the read-type data quality summary generator (`ReadTypeDataQualitySummaryGenerator`) but are never emitted by the half-hourly or daily generators — `negative` and `wrongUnits` counts in `serl_smart_meter_rt_summary_edition08.csv` are always `0` in the current mock data.
